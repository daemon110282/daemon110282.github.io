## Зачем

Нужны для подтверждения подлинности участников информационного взаимодействия, обеспечения защищённого обмена данными и установления доверия между системами.
Сертификат безопасности — это __цифровое удостоверение__, позволяющее информационным системам __проверять, кому они доверяют,__ с кем устанавливают соединение и каким __открытым ключом можно пользоваться__.

Use case:

- Аутентификация
  - Подтверждение подлинности сервера или клиента
  - Проверка, что пользователь подключился к настоящему bank.ru
  - Клиентский client certificate для аутентификации систем __[Mutual TLS](../../../technology/protocols.integration/tls.md) (mTLS)__
- Шифрование
  - Обеспечение конфиденциальности передаваемых данных
  - HTTPS-соединение между браузером и сервером
  - TLS-сертификаты для защиты каналов связи
- Целостность
  - Обнаружение изменения данных при передаче
  - Проверка целостности сообщения
- Электронная подпись
  - Подтверждение авторства и целостности документа
  - Подписание договора электронной подписью
- Доверие
  - Подтверждение того, что сертификат выдан доверенным удостоверяющим центром
  - Проверка цепочки сертификатов

## Термины

- Сертификат - Связь открытого ключа с идентичностью
- Открытый ключ - Используется для проверки подписи или шифрования
- Закрытый ключ - Используется для создания подписи или расшифрования
- CA -Удостоверяющий центр, выпускающий сертификаты
- PKI - Инфраструктура управления ключами и сертификатами
- TLS - Протокол защищённого обмена данными
- mTLS - TLS с взаимной аутентификацией клиента и сервера
- CRL / OCSP -Механизмы проверки отзыва сертификатов
- Self-Signed Certificate (самоподписанный сертификат) — это цифровой сертификат, который подписан __собственным закрытым ключом владельца__, а не __удостоверяющим центром__ (CA — Certificate Authority). Иными словами, организация или разработчик самостоятельно создаёт сертификат и подписывает его, не обращаясь к внешнему доверенному удостоверяющему центру.
  - Проблема заключается в том, что без предварительной настройки доверия __клиент не может надёжно подтвердить подлинность сервера__.

## Структура сертификата

Обычно сертификат X.509 содержит:

- Subject — кому принадлежит сертификат (домен, организация, пользователь).
- Issuer — кто выпустил сертификат (Certificate Authority).
- Public Key — открытый криптографический ключ.
- Serial Number — уникальный серийный номер.
- Validity — период действия.
- Signature Algorithm — алгоритм электронной подписи сертификата.
- CA Signature — подпись удостоверяющего центра.
- Extensions — дополнительные параметры, например назначение ключа и альтернативные имена доменов.

## Основные виды сертификатов

| Тип                | Назначение                     | Пример использования                             |
| ------------------ | ------------------------------ | ------------------------------------------------ |
| SSL/TLS            | Защита соединений              | HTTPS на сайте                                   |
| Client Certificate | Аутентификация клиента         | Взаимодействие между API                         |
| Code Signing       | Подтверждение подлинности ПО   | Подписание установщика приложения                |
| Document Signing   | Электронная подпись документов | Подписание договора                              |

| Intermediate CA    | Промежуточный сертификат       | Выпуск пользовательских и серверных сертификатов |

## Как работает сертификат при HTTPS

Последовательность:

1. Браузер подключается к серверу по HTTPS.
2. Сервер отправляет браузеру свой TLS-сертификат.
3. Браузер проверяет:
   - срок действия сертификата;
   - соответствие доменного имени;
   - подпись удостоверяющего центра;
   - цепочку доверия;
   - статус отзыва сертификата (если проверка выполняется).
4. При успешной проверке устанавливается защищённое TLS-соединение.
5. Данные передаются в зашифрованном виде.

Если сертификат недействителен, браузер может показать предупреждение о небезопасном соединении.

## Цепочка доверия (Certificate Chain)

Цепочка доверия обычно состоит из трёх уровней:

1. Root CA — корневой сертификат, которому доверяет операционная система или браузер.
2. Intermediate CA — промежуточный удостоверяющий центр.
3. End-Entity Certificate — сертификат конкретного сервера, клиента или пользователя.

Доверие к конечному сертификату устанавливается через проверку всей цепочки до доверенного корневого сертификата.
